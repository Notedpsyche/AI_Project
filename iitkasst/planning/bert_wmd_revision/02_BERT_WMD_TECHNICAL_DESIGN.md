# BERT + WMD Technical Design

## 1. Academic status

The implementation is a genuine adaptation of the paper, not an exact reproduction. It uses the same model family, independent vocabulary-word encoding, 768-dimensional hidden representations, term-frequency distributions, Euclidean ground cost, and exact optimal transport. It differs because the paper's private fine-tuned BERT checkpoint and banking vocabulary are unavailable; this project uses an unfine-tuned public BERT checkpoint, explicit WordPiece behavior, normalized vectors, and college chunks.

Using unfine-tuned BERT is academically sufficient if reported as **pretrained BERT + exact WMD adaptation** and evaluated honestly. It must not be described as reproducing the paper's fine-tuned classifier or results.

## 2. Model selection

Use `google-bert/bert-base-uncased` pinned to revision `86b5e0934494bd15c9632b12f734a8a67f723594`.

- 12 encoder layers, 12 attention heads, hidden size 768, vocabulary size 30,522, maximum input length 512.
- About 110M parameters and Apache-2.0 license.
- Supported by the already installed PyTorch and Transformers stack on CPU and CUDA.
- Better paper fidelity than DistilBERT, whose six-layer architecture has no direct “layer 11.”
- Lower memory than BERT-large and adequate for single-word batched encoding.
- `bert-base-cased` would preserve case, but the paper lowercases and college abbreviations can be normalized deterministically; uncased is the selected model.

The model weights are roughly 440 MB in float32 before framework/runtime overhead. A practical inference process should fit comfortably on the 6 GB RTX 4050 when run separately. This is a feasibility expectation, not a measured promise; implementation must record peak VRAM and CPU fallback latency.

## 3. Shared preprocessing

Implement one versioned `WmdPreprocessor` used for corpus cache creation and every query:

1. Unicode NFKC normalization and `.casefold()`.
2. Normalize common punctuation inside known forms before token splitting: `b.tech→btech`, `m.tech→mtech`, `e-m.tech→emtech`, `ph.d→phd`; preserve `cse`, `ece`, `ai`, `2026`, semester numbers, and currency-bearing digits as lexical terms.
3. Extract alphanumeric surface terms; punctuation itself carries no mass.
4. Remove a versioned English stopword set, but retain negation and temporal/ordinal words such as `not`, `without`, `before`, `after`, `first`, and `last`.
5. Do not stem or lemmatize. WordPiece already handles subword structure, and stemming would create artificial nonwords.
6. Preserve repeated surface terms for term-frequency mass.
7. Enforce query/document field caps before embedding lookup.

The exact aliases and stopword hash are part of the cache manifest. Preprocessing changes invalidate the cache.

## 4. Word representation

For each distinct preprocessed surface word `w`:

1. tokenize `w` with `AutoTokenizer` using special tokens, producing `[CLS], p1, …, pk, [SEP]`;
2. reject a word if it produces no lexical piece or includes `[UNK]`;
3. run `AutoModel(..., output_hidden_states=True)` in `eval()` and `torch.inference_mode()`;
4. select `hidden_states[-2][0, 0, :]`, the `[CLS]` position from encoder layer 11;
5. convert to CPU float32 and L2-normalize with an epsilon guard;
6. store one 768-dimensional vector under the surface word, not under each WordPiece.

Attention masks are generated by the tokenizer; padding positions never contribute because the selected position is `[CLS]`. Cache builds batch words with dynamic padding. Special-token outputs are never vocabulary entries.

This approach intentionally does **not** average WordPiece vectors. The pieces influence the `[CLS]` representation through attention, which is the closest inspectable implementation of the paper's first-sequence-output description. Because the paper is ambiguous about hidden-state indexing, the manifest calls this `encoder_layer_11_cls` and tests assert `hidden_states[-2]`, avoiding silent off-by-one changes.

## 5. Query and document measures

### Query

Use the effective query produced by existing context resolution. Preprocess and cap it at 32 lexical token occurrences. Collapse occurrences to ordered unique terms with counts. Terms absent from the persistent corpus cache are encoded lazily and retained in a bounded in-process LRU keyed by the same model/preprocessing signature.

### Document

For every chunk, construct a maximum 64-token representation:

- up to 12 tokens from the source title;
- up to 20 tokens from the leaf heading (or title if no heading);
- up to 32 tokens from passage text.

Unused field capacity is not reallocated in the first implementation; this makes field influence deterministic. Duplicate terms across fields increase their term frequency. Full 220-word text is deliberately excluded because it increases the cost matrix, dilutes heading intent with unrelated mass, and makes timing less predictable.

For terms `t_i` with counts `c_i`, define normalized mass:

`a_i = c_i / Σ c_i` and `b_j = c_j / Σ c_j`.

Repeated terms therefore carry more mass while the source and target distributions each sum to one.

## 6. Exact WMD

Let normalized BERT vectors be `x_i` for query terms and `y_j` for document terms. Construct the Euclidean ground-cost matrix:

`M_ij = ||x_i - y_j||_2`.

Solve:

`min_T Σ_i Σ_j T_ij M_ij`

subject to:

- `T >= 0`;
- `T 1 = a`;
- `Tᵀ 1 = b`.

Use `ot.emd2(a, b, M)` from [Python Optimal Transport](https://pythonot.github.io/gen_modules/ot.lp.html). POT documents this as exact linear optimal transport using a CPU C++ backend. Lower distance means less semantic transport cost and therefore greater similarity.

Implementation safeguards:

- cached embeddings are float32, but `a`, `b`, and contiguous `M` are converted to float64 for the solver;
- assert finite vectors/costs, nonnegative costs, positive total mass, and marginal sums within `1e-12` before solving;
- clamp only tiny negative floating-point output (`>-1e-10`) to zero; reject larger negative/nonfinite values;
- empty preprocessed query/document returns a typed `EmptyDistributionError`, never distance zero;
- token caps constrain `M` to at most `32 × 64` for normal use;
- solver exceptions are attached to the candidate trace and do not crash the baseline;
- a wall-clock budget is checked between candidates. POT has no safe in-process hard timeout for one network-simplex call, so the small matrix cap is the primary bound; a subprocess timeout is a future hardening option.

Sinkhorn and Relaxed WMD are not used initially. Sinkhorn adds entropic regularization and is approximate; Relaxed WMD drops transport constraints and is a lower bound. Either would require explicit alternate labels and separate metrics.

## 7. Ranking

`WmdReranker.rerank(query, candidates, limit=15)`:

1. rejects `limit > configured_max_candidates`;
2. preserves each candidate's complete existing dictionary;
3. computes one distance for each eligible candidate;
4. adds `wmd_distance`, `wmd_rank`, `wmd_elapsed_ms`, and `wmd_status` to copies;
5. sorts finite distances ascending, breaking ties by original RRF rank then chunk ID;
6. places failed candidates after successful candidates without losing metadata.

The first experiment uses top 15 eligible RRF candidates. This is a reranking experiment and cannot improve Recall@15 of the shared pool. It can improve MRR/nDCG/top-k precision only when the gold passage is already in that pool.

For a paper-style secondary experiment, metadata-filter the full eligible 98-chunk corpus and rank it with WMD. Report it separately as standalone candidate generation. Do not compare its recall against a shared-pool reranker without the distinction.

## 8. Centroid and hybrid baselines

The paper-style centroid baseline uses the same token vectors and masses: `q̄ = Σ a_i x_i`, `d̄ = Σ b_j y_j`, then cosine similarity. It is not WMD.

The only initial BM25/WMD hybrid is rank fusion:

`score(d) = 1/(k + rank_BM25(d)) + 1/(k + rank_WMD(d))`, with `k=60`.

This is mathematically safe under incompatible score scales. A future development-only interpolation may min-max normalize BM25 and convert WMD to relevance with `1 - normalized_distance`, but it is sensitive to candidate-set outliers and is not selected for the presentation.

## 9. Cache and reproducibility

Artifacts:

- `vocabulary.json`: sorted token list;
- `embeddings.npy`: row-aligned float32 matrix `[V, 768]`;
- `documents.json`: chunk ID to bounded token/count representation;
- `manifest.json`: complete compatibility contract.

Load with `mmap_mode="r"` where practical. Validate token count, matrix shape/dtype, corpus SHA-256, model revision, tokenizer, hidden-state selector, preprocessing hash, representation limits, and schema version before use.

Memory for vectors is `V × 768 × 4` bytes: about 3.0 KB/token, 15.4 MB for 5,000 words, and 63.8 MB for the paper's 20,772-word scale. The current 98-chunk corpus should be below that upper example, but implementation will record the actual vocabulary and file size rather than claim an estimate as measurement.

## 10. Dependency and platform contract

Already installed locally: PyTorch 2.6.0+cu124, Transformers 5.19.0 (transitive), NumPy 2.5.3, SciPy 1.18.1, Sentence Transformers 6.1.0. Add two direct project declarations:

- `transformers>=5.19,<6` because project code will import it directly;
- `POT==0.9.7` for `ot.emd2`.

POT 0.9.7 is MIT-licensed and currently publishes Windows-compatible distributions through [PyPI](https://pypi.org/project/POT/). The implementation preflight must run an import plus the tiny exact-transport test before downloading BERT. If a compatible Windows wheel cannot resolve in the existing Python environment, stop Stage 3 and preserve the baseline; do not substitute cosine or approximate transport under the WMD name.

## 11. Resource expectations and checks

Expected—not guaranteed—fit: approximately 440 MB BERT weights, modest batched single-word activations, a tens-of-megabytes vocabulary cache, and small CPU OT matrices. Run BERT cache creation and the existing BGE backend in separate processes for the presentation unless concurrent VRAM is measured safe.

Concrete implementation checks:

- measure model load time, cache-build time, per-query encoding time, per-candidate OT time, total top-15 rerank p50/p95, peak process RSS, and `torch.cuda.max_memory_allocated()`;
- confirm CPU fallback completes the five-query smoke set;
- stop production-integration work if top-15 warmed p95 exceeds 2 seconds beyond baseline or if the experiment destabilizes the baseline process. The CLI may still be demonstrated with recorded honest latency.
